# Desktop-приложение CZCraftCalc

Это технический прототип связки **Tauri 2 + общий React frontend + Python backend через IPC**.

Frontend расположен в корневом каталоге `frontend/` и используется как Desktop-интерфейс, а также как Web-интерфейс. В desktop-версии через IPC подключены список предметов, категории, карточка предмета и её варианты, расчёт рецепта, пакетный анализ, история сделок и рыночная аналитика. FastAPI, HTTP API и localhost для обмена между frontend и Python не запускаются.

## Что потребуется

- Windows 10/11 x64;
- Rust stable и Cargo;
- Tauri CLI 2;
- Node.js LTS и npm;
- Python 3.10+;
- установленный WebView2 Runtime (обычно уже есть в Windows 11).

## Получение исходников и запуск

Из корня репозитория установите frontend-зависимости:

```powershell
cd frontend
npm ci
cd ..
```

Создать виртуальное окружение Python в корне backend:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Создать корневой `.env` из `.env.example` и заполнить необходимые параметры.

Указать интерпретатор Python для Tauri:

```powershell
$env:CZCRAFTCALC_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
```

Установить Tauri CLI (один раз):

```powershell
cargo install tauri-cli --version "^2"
```

Запустить приложение из каталога `desktop`:

```powershell
cd desktop
cargo tauri dev
```

## Как устроен обмен

1. React вызывает глобальный Tauri API `window.__TAURI__.core.invoke`.
2. Rust-команда запускает `desktop/python/bridge.py`.
3. Команда передаётся Python через stdin одной JSON-строкой.
4. Python вызывает существующие обработчики и бизнес-логику backend.
5. Результат возвращается одной JSON-строкой через stdout.

Каждый вызов запускает отдельный короткоживущий Python-процесс. Это сделано для первого прототипа: так проще проверить архитектуру и изоляцию ошибок. Для полноценной версии можно перейти на постоянно работающий процесс с двусторонним IPC.

## Ограничения прототипа

- Страницы используют существующие обработчики `server.routes` напрямую. Это сохраняет бизнес-логику веб-версии и не поднимает HTTP-сервер.
- Иконки предметов передаются в UI как data URI; сами файлы остаются в локальной базе данных.
- Справочные данные при необходимости загружаются backend из официального репозитория игровых данных.
- Для операций, которые обращаются к STALCRAFT API, пока может требоваться OAuth client secret из локального корневого `.env`.
- Секрет нельзя встраивать в публичный desktop-бинарник: извлечь его из приложения технически возможно. Модель OAuth для распространения приложения будет определена отдельно.
- Это dev-прототип, а не готовый установщик. Упаковка Python runtime, подпись и безопасное хранение пользовательских настроек пока не реализованы.

## Диагностика

Если Python не найден, задайте `CZCRAFTCALC_PYTHON` на полный путь к `python.exe`.

Если операция сообщает об ошибке OAuth, проверьте корневой `.env`. Не публикуйте этот файл и не отправляйте его содержимое в логах.
